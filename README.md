# متجر تيليجرام — Cloudflare Workers + D1

مشروع متجر رقمي عربي يعمل من داخل Telegram باستخدام **JavaScript ES Modules** و **Cloudflare Workers** و **Cloudflare D1**. الإصدار الحالي أساس وظيفي قابل للتوسع، وليس متجر إنتاج مُنشَراً أو خدمة مدفوعات مفعلة. تم تطوير واجهة المدير في النسخة الثانية مع المحافظة على حماية مفاتيح Cloudflare.

## الميزات المنفذة

- Webhook آمن باستخدام `X-Telegram-Bot-Api-Secret-Token`.
- القائمة الرئيسية، الأقسام، البحث، تفاصيل المنتجات، المنتجات المميزة والمفضلة.
- صفحة الملف الشخصي، المحفظة الداخلية، سجل الرصيد، سجل الطلبات ورابط الإحالة.
- طلب شراء المنتج -> موافقة المدير -> إرسال فاتورة Telegram Stars -> إشعار الدفع -> تسليم يدوي أو استرداد.
- مخزون محجوز عند موافقة المدير ويُعاد عند رفض طلب غير مدفوع أو استرداد مدفوع لم يُسلّم.
- تسجيل طلب شحن يدوي (آسيا سيل/زين كاش/سوبر كي) بمبلغ + رقم مرجع + صورة اختيارية -> موافقة/رفض المدير. **الميزة معطلة افتراضياً** إلى حين تحديد الاستخدام المسموح وإعداد معلومات الحسابات.
- سجل مالي بقيود D1 وعمليات فريدة، منع إضافة شحن مرتين، معاملات ذرية عند الموافقة.
- إدارة **خاصة بمالك واحد** عبر `/admin` أو زر خاص يظهر في القائمة الرئيسية لحساب المدير فقط: الطلبات والشحن، المنتجات والأقسام والأسعار والمخزون وأوصاف المنتجات وتعليمات تسليمها وإظهارها وإخفاؤها، إدارة العملاء وحظرهم، الإحصائيات، وسياسات المتجر وتعليماته.
- تعديل الرسالة الحالية في التنقل عبر `editMessageText` متى سمح تيليجرام بذلك، وفتح القائمة بسرعة عبر أزرار Inline.
- طابور إشعارات يسعى لإعادة الإرسال تلقائياً كل خمس دقائق.
- الدعم والمراسلات الإدارية وواجهة عربية.

## التشغيل 24/7 والأداء

Workers هو نظام **بدون خادم دائم**: يرد عند وصول تحديث Telegram Webhook حتى لو لم يستخدم البوت أحد منذ أيام. لا يحتاج إلى ping وهمي أو جهاز يعمل باستمرار. تعمل مهمة Cron كل خمس دقائق لمعالجة الإشعارات العالقة (وليس لإبقاء البوت حياً). الاستمرارية تعتمد على تشغيل Cloudflare وTelegram والالتزام بحدود الاستخدام، وليست ضماناً مطلقاً بنسبة 100%.

تقلل الواجهة تحديثات الرسائل وترد على ضغطات الأزرار فوراً. اختبر زمن الاستجابة من العراق على حساب Cloudflare الحقيقي بعد الإطلاق التجريبي؛ لا توجد أرقام سرعة مضمونة مسبقاً.

**Cloudflare Email لا يمنح هذا المشروع حق الدخول للحساب تلقائياً.** يلزم تسجيل الدخول من حسابك وربط GitHub، ولا تضع كلمة المرور أو Bot Token في المحادثة أو GitHub.

## لوحة المدير الخاصة بك

عند إعداد Cloudflare Secret باسم `ADMIN_ID` بالمعرف الرقمي الخاص بحسابك فقط:

- يظهر زر **🛡️ لوحة تحكم المدير** في `/start` لحسابك وحده.
- يستطيع المدير فقط الدخول إلى `/admin` أو تشغيل الأزرار الإدارية حتى لو حاول عميل تزوير `callback_data`.
- أقسام الإدارة: طلبات الشحن والشراء والتسليم، المنتجات وأسعارها، المخزون، الإظهار والإخفاء، الأقسام، العملاء والحظر، إحصائيات المتجر والإعدادات.
- من **⚙️ الإعدادات والتعليمات** تستطيع تعديل: اسم المتجر، الترحيب، تعليمات المتجر والشراء والشحن والدفع والتسليم، الدعم، الشروط، الخصوصية، قناة الأخبار، بيانات حسابات الاستلام، وإيقاف استقبال طلبات جديدة مؤقتاً.
- من تفاصيل المنتج يمكنك تعديل الوصف والسعر والمدة والمخزون والتعليمات الخاصة بالتسليم، ونقله إلى قسم آخر.
- كلمة `/cancel` تلغي وضع التحرير الحالي. يوجد أمر `/id` لعرض معرف Telegram ID لحساب المستخدم في الخاص.
- لا يمكن إدارة الأسرار أو تغيير المدير من داخل تيليجرام؛ تُدار من Cloudflare حصراً.

## قبل التشغيل

تحتاج إلى حساب Cloudflare وحساب Telegram BotFather. لا تحفظ الرموز داخل GitHub.

1. أنشئ بوتاً عبر [BotFather](https://t.me/BotFather) واحصل على رمز البوت. احفظه خارج المحادثة والمستودع.
2. ثبّت Node.js 20 أو أحدث، ثم نفّذ `npm install`.
3. سجّل دخول Cloudflare من الجهاز الموثوق: `npx wrangler login`.
4. أنشئ D1: `npx wrangler d1 create telegram_store`.
5. استبدل قيمة `database_id` الوهمية داخل `wrangler.jsonc` بالمعرف الذي يعطيه Cloudflare.
6. نفّذ `npm run db:remote` لتطبيق **جميع** ملفات migrations (0001 و0002) على D1 الإنتاج.
7. أنشئ الأسرار بالترتيب:
   - `npx wrangler secret put TELEGRAM_BOT_TOKEN`
   - `npx wrangler secret put WEBHOOK_SECRET` (حروف وأرقام و `_` أو `-`، عشوائي وقوي)
   - `npx wrangler secret put ADMIN_ID` (Telegram ID الرقمي **الوحيد** للمدير؛ لا تستخدم اسم المستخدم أو البريد الإلكتروني)
8. عدّل `BOT_USERNAME` و`STORE_NAME` في `wrangler.jsonc`. أدخل أرقام الاستلام العامة **فقط عندما تكون الميزة مسموحة ومفعّلة**.
9. انشر: `npm run deploy`.
10. سجّل عنوان Webhook بعد النشر باستخدام القيم في **متغيرات بيئة جهازك المحلية فقط**: `TELEGRAM_BOT_TOKEN=... WEBHOOK_SECRET=... WORKER_URL=https://... npm run webhook`.
11. ابدأ محادثة مع البوت، أرسل `/start`. ثم من حساب المدير أرسل `/admin`.

> الأمر `npm run webhook` ينشئ Webhook لدى تيليجرام. لا تضف قيم الأسرار إلى README أو إلى أمر منشور علناً أو محادثة.

## إدارة المنتجات

- `/admin` يفتح لوحة الإدارة.
- زر **إضافة منتج**: أرسل `الاسم | رقم القسم | السعر بالنجوم | المدة بالأشهر أو - | المخزون أو - | الوصف`.
- `/setproduct 1 price_stars 25` لتغيير سعر المنتج رقم 1 إلى 25 نجمة.
- `/setproduct 1 stock 5` لتغيير المخزون.
- `/setproduct 1 active 0` لإخفائه.
- `/setproduct 1 featured 1` لتثبيته في الرئيسية.
- `/reply 123456789 نص الرد` للرد على عميل من الدعم.

لم تُضف أي منتجات قابلة للبيع افتراضياً؛ ينبغي فقط إدخال الخدمات المرخص لك ببيعها.

## المدفوعات والمحفظة

بيع الخدمات والسلع الرقمية **داخل Telegram** يتم بعملة **Telegram Stars (`XTR`)**، وفق قواعد تيليجرام. عند الموافقة على الطلب لا تُحصّل نجوم العميل آلياً؛ بل ترسل له فاتورة ويجب أن يدفعها. لا يعتبر الطلب مدفوعاً إلا بوصول `successful_payment` المطابق. يمكن للمدير استرداد النجوم لطلب مدفوع لم يُسلّم بعد.

المحفظة بـ IQD منفصلة. **لا تستخدم شحن المحفظة من آسيا سيل أو زين كاش أو سوبر كي بديلاً لشراء السلع الرقمية داخل البوت.** ميزات الشحن اليدوي بنيت كوحدة منفصلة مع إيقافها افتراضياً (`ENABLE_MANUAL_TOPUPS=false`). عند الحاجة إلى تفعيلها لاستخدام مسموح، قم أولاً بضبط `ENABLE_MANUAL_TOPUPS=true` وتعبئة بيانات الاستلام العامة. التحقق من وصول التحويل يتم يدوياً ولا يمكن اعتبار صورة الإيصال وحدها إثباتاً نهائياً.

## حالة التطوير والقيود

هذه **النسخة الأساسية قيد التطوير**؛ وليست نسخة مطابقة 100% للفيديو المرجعي. القوائم الرئيسية تحاول تعديل الرسالة نفسها عند التنقل، بينما بعض عمليات الشراء والإدارة تنشئ رسائل جديدة عمداً. يتطلب التطابق البصري الكامل مع الفيديو مرحلة مراجعة إضافية. أزرار Telegram ذات ألوان وأبعاد تخضع لقيود تطبيق Telegram، ولا يمكن التحكم في لونها بالبكسل.

ما يزال مطلوباً قبل الإنتاج: مطابقة بقية الشاشات مع الفيديو، توسعة إدارة الطلبات، إكمال ترجمة اللغات، دعم كميات متعددة، مراجعة حالات استرداد فشل قاعدة البيانات بعد نجاح API، اختبارات Cloudflare staging الفعلية، إعداد شروط الاستخدام والخصوصية، ومراجعة المبيعات والتراخيص الخاصة بالاشتراكات.

لا تعلن جاهزية الدفع الحقيقي أو نشر البوت للعامة حتى يتم اختبار Webhook وD1 وعمليات Telegram Stars في بيئة اختبار.

## تحسينات سرعة الواجهة والموثوقية

- تفتح صفحات لوحة المدير بتعديل رسالة القائمة في مكانها متى سمح تيليجرام بذلك، دون تراكم رسائل جديدة.
- يتم منع طلبين من ضغطة مزدوجة على نفس رسالة تأكيد الشراء حتى لو اختلف معرف ضغط الزر.
- تؤجل الإشعارات الفاشلة تدريجياً لتقليل الاستدعاءات المتكررة عند تعطل Telegram أو حدوث حد المعدل.
- يستخدم الإصدار الثالث `migrations/0003_reliability.sql`، ويجب تطبيقه قبل نشر الكود الجديد.

## V7 — القوائم الملونة وقائمة الأوامر الأصلية

- أول أربعة خيارات في الرئيسية خضراء، وبقية خيارات القائمة الأساسية تستخدم `primary` (لون تيليجرام الأساسي حسب ثيم العميل).
- الأزرار الداخلية الافتراضية ملونة، وتبقى ألوان الحالات `success` للمخزون المتوفر و`danger` للمخزون الذي يساوي صفراً، مع الكمية وزر `🔄 تحديث المخزون`.
- صفحة الملف الشخصي تعرض المعرّف والرصيد والإحالات والمشتريات الفعلية من قاعدة البيانات، يليها خمسة أزرار كاملة الصف: شحن الرصيد، طلباتي، سجل العمليات، المفضلة، رجوع.
- القائمة ذات الخطوط الثلاثة هي **قائمة أوامر تيليجرام** (`setMyCommands` + `setChatMenuButton`)، وليست `ReplyKeyboardMarkup` ثابتاً. تحتوي الأوامر العامة على `/menu`, `/shop`, `/topup`, `/profile` وغيرها، ويضاف `/admin` إلى القائمة الخاصة بمعرّف المالك فقط عبر نطاق chat.
- لا تغيّر هذه النسخة تدفق الشحن V6 أو أرصدة D1، ولا تتطلب أي Migration جديد؛ لا يبدأ نشر الإنتاج تلقائياً عند تحديث GitHub.
- يجب إجراء اختبار حقيقي في تيليجرام بعد النشر للتحقق من دعم ألوان الأزرار في عميل المستخدم ومن ظهور زر الأوامر الأصلية؛ لا يمكن فرض لون بكسل أو شكل واجهة التيليجرام من Bot API.

## تصحيح إعدادات المحفظة وتوضيح صلاحية المدير
- تم إزالة العبارة التي تبدو كخطأ صلاحيات من لوحة المدير، واستبدالها بتوضيح أن حساب المدير معتمد.
- داخل لوحة المدير زر **⚙️ إعداد شحن المحفظة** يبين الحالة الفعلية وسعر الصرف والحسابات المضافة، مع روابط مباشرة لإدخال بيانات الاستلام والتفعيل.
- يمكن للمدير **اعتماد 1 USD = 1,520 IQD** بنقرة صريحة أو كتابة سعر مخصص؛ لا يتم تخمين سعر السوق ولا يتم تشغيل استقبال طلبات الشحن قبل وجود وسيلة استلام.
- عند عدم وجود طلبات شحن تُعرض رسالة واضحة وتُحدث الرسالة الحالية، بدلاً من بقاء النص القديم الذي يسبب التباساً.
- موافقات الشحن والرصيد الحالي محفوظان كما كانا؛ لا تعديلات مباشرة على قاعدة الإنتاج في هذا التحديث.
